# Killing Floor Mutator Tools

[English](../../README.md) · **Русский** · [Español](./README.es.md) · [Português](./README.pt.md) · [Lietuvių](./README.lt.md) · [Polski](./README.pl.md) · [Français](./README.fr.md) · [中文](./README.zh.md) · [日本語](./README.ja.md)

Компилирует мутаторы для **Killing Floor 1** (UnrealScript, Unreal Engine 2.5), запуская родной `UCC.exe` от Tripwire в изолированной рабочей папке. Клиент игры даёт пакеты и контент, выделенный сервер даёт компилятор, а **папка игры только читается** — в неё ничего не добавляется, не изменяется и не удаляется.

Одна сборка, три интерфейса: CLI, браузерный UI и десктопное приложение для Windows, macOS и Linux.

> `ucc make` нигде не задокументирован, возвращает `0` при части ошибок и молча меняет разрешение имён, если собирать пакеты пачкой. Всё, что приходится обходить при сборке, измерено и записано в [`docs/GOTCHAS.md`](../GOTCHAS.md); как именно управляют компилятором и почему нужен клиент игры, а SDK не нужен — в [`docs/RESEARCH.md`](../RESEARCH.md).

## Что нужно

- Локально установленный клиент **Killing Floor** ([appid 1250](https://store.steampowered.com/app/1250/)) — DLL-ки, штатные `.u`-пакеты и весь контент. Именно на него указывает `gamePath`.
- **`UCC.exe`**, то есть [Killing Floor Beta Dedicated Server](https://steamdb.info/app/1273/) (appid 1273, в библиотеке Steam → Tools, бесплатно вместе с игрой), если у тебя ещё нет этого бинарника откуда-то ещё.
- **Windows** либо [Wine](https://www.winehq.org/) на Linux и macOS.
- Только для CLI: [Node.js](https://nodejs.org) 18 или новее. Десктопное приложение несёт свой рантайм с собой.

В репозитории нет ни игрового контента, ни `UCC.exe` — это бинарник Tripwire. Инструмент направляют на уже имеющуюся у тебя копию.

Killing Floor SDK **не нужен**: он не добавляет ничего, что требуется компилятору. Выделенный сервер **не заменяет** клиент — в нём примерно половина контента, и одного отсутствующего `2K4Menus` достаточно, чтобы сборка развалилась. Оба вывода разобраны в [`docs/RESEARCH.md`](../RESEARCH.md).

## Десктопное приложение (Windows / macOS / Linux)

Готовые самодостаточные сборки — на странице [Releases](https://github.com/TheBestPlan/killingfloor-mutator-tools/releases):

- **Windows** — `…-setup.exe` (установщик) или `…-portable.exe` (запуск без установки).
- **macOS** — `…-mac-x64.dmg` (Intel) или `…-mac-arm64.dmg` (Apple Silicon).
- **Linux** — `…-linux-x86_64.AppImage` (запускается где угодно) или `…-linux-amd64.deb`.
- **Только CLI** — `killingfloor-mutator-tools-<version>.tgz`, тот же инструмент без Electron: `npm install -g killingfloor-mutator-tools-<version>.tgz`.

Укажи установленный Killing Floor (или нажми **Detect**), добавь папки своих пакетов, нажми Build и смотри, как в реальном времени идёт лог компилятора. В шапке есть переключатель языка — те же девять языков, что и у этого README; выбор запоминается. Сборки не подписаны, поэтому при первом запуске система может предупредить (Windows SmartScreen → *Подробнее → Выполнить в любом случае*; macOS → правый клик → *Открыть*).

### Собрать самому

```bash
pnpm install
pnpm start          # запустить приложение из исходников
pnpm run dist       # собрать установщики для текущей ОС в dist/
```

## CLI

```bash
pnpm run detect                                  # заполнить gamePath/uccPath из локальных библиотек Steam
pnpm run check                                   # проверить конфиг без компиляции
pnpm run build                                   # собрать все пакеты из конфига
pnpm run gui                                     # браузерный UI на http://127.0.0.1:7331

node bin/killingfloor-mutator-tools.js build KF15BetaMutators   # собрать один из них
```

`--config=<dir>` указывает на папку с `killingfloor-mutator-tools.config.json` (по умолчанию — текущая), поэтому сам инструмент может лежать где угодно и собирать репозиторий мутаторов в другом месте.

## Конфигурация

`killingfloor-mutator-tools.config.json` рядом с тем местом, откуда запускается команда. Начни с копии `killingfloor-mutator-tools.config.example.json`; `detect` заполнит два пути за тебя. Прямые слэши работают и в Windows и избавляют от экранирования в JSON.

| ключ | что значит |
| --- | --- |
| `gamePath` | корень установленного Killing Floor |
| `uccPath` | `UCC.exe`; пусто = автопоиск по библиотекам Steam, сначала выделенный сервер |
| `workspace` | изолированная папка сборки, её безопасно удалять; держи имя коротким, потому что UCC не умеет длинные пути |
| `packages` | папки с исходниками мутаторов (в каждой есть `Classes/`), **в порядке сборки** |
| `resourcePaths` | корни с `System/`, `Textures/`, `Sounds/`, `StaticMeshes/`, `Animations/`, где лежит кастомный контент и заранее собранные пакеты-зависимости |
| `outputPath` | куда попадают `.u`, `.ucl` и `.uz2` |
| `copyTo` | дополнительные папки, куда положить `.u`/`.ucl` — например `System/` сервера или папка ресурсов docker |
| `strip` | запускать `Editor.StripSourceCommandlet`, который примерно вдвое уменьшает `.u` |
| `compress` | делать `.uz2` для HTTP-редиректа |
| `buildInfoClass` | класс, в дефолт `Version` которого штампуется время сборки и git-хеш; `""` отключает |
| `wine` | команда Wine на не-Windows хостах |

Все ключи с примерами — в [`docs/USAGE.md`](../USAGE.md).

## Как сборка остаётся изолированной

Инструмент собирает **рабочую папку**: приватный `System/` с `UCC.exe`, DLL-ками и `.int`-файлами игры и сгенерированным `KillingFloor.ini`, в котором `[Core.System] Paths` смотрят прямо в игровые `Textures/`, `Sounds/`, `StaticMeshes/`, `Animations/`, `Maps/` и `System/`. Исходники копируются внутрь, компилятор работает там, артефакты выносятся наружу.

```
<workspace>/
  System/          UCC.exe + DLL игры + *.int + сгенерированный KillingFloor.ini   (~19 МБ)
  <Package>/       копия твоих исходников Classes/
```

DLL-ки приходится именно копировать, а не ссылаться на них: UCC определяет свою базовую папку по тому, откуда была загружена `Core.dll`, так что оставь их в папке игры — и компилятор начнёт писать туда свой вывод и свои логи.

## Структура

| Путь | Что это |
|------|-----------|
| `src/build.js` | ядро: поиск в Steam, подготовка рабочей папки, генерация ini, запуск UCC и разбор его ошибок |
| `src/gui.js` | локальный сервер за интерфейсом (только `127.0.0.1`) |
| `src/gui.html` | интерфейс сборки: форма конфига, кнопки Detect / Save / Check / Build, живой лог компилятора |
| `src/i18n.js` | переводы интерфейса на девять языков README, с живым переключением |
| `bin/killingfloor-mutator-tools.js` | CLI |
| `electron/main.js` | оболочка Electron, показывающая тот же интерфейс как десктопное приложение |
| `test/smoke.js` | офлайн-проверки генерации ini, подготовки зависимостей и детекта ошибок |
